# Life Console 苹果式 UI/UE 长期设计规范

本规范用于后续 Agent 协同维护 `apps/life-console/` 前端与相关设计原型。它只描述通用产品与界面规则，不写入个人日记、健康明细、外部账号绑定或机器私有运行态。

## 设计目标

- 降低认知负担：首屏只呈现今天最需要知道的一件事、一个建议行动和少量待确认事项。
- 保留用户控制感：写入、删除、覆盖、同步和外部动作必须清楚区分“预览”“确认”“已保存”。
- 守住真相源边界：iCloud 项目是个人数据真相源；网页与图表只做投影，不反向推断或补写。
- 避免压力型反馈：不使用完成百分比、连续打卡惩罚、人格判断或虚构紧迫感推动用户。

## 信息架构

- `工作台总览`：今天的重点、建议行动、生活锚点、待确认与保存链路。
- `记录输入`：对话式记录为主入口；简洁表单为兜底；高级字段默认折叠。
- `进展洞察`：展示自然周路径、阶段路线、四项主观评分和睡眠结构；趋势只辅助判断。
- `系统边界`：展示本机服务、iCloud、自动化、备份、Google 表格、移动端与一期边界。

## 视觉系统

- 采用苹果式克制表达：黑、白、软灰为主，蓝色只用于主操作、当前状态和少量强调。
- 顶部全局导航高度为 `44px`，可使用毛玻璃背景；导航 active 只使用一种强调方式。
- 页面宽度建议 `min(1180px, calc(100% - 48px))`，首屏留白优先于塞满信息。
- 卡片以 `1px` 边框和轻阴影定义层级；默认不要使用重阴影、彩色块或多层嵌套卡片。
- 按钮使用胶囊形态；一个区域只保留一个主按钮，按钮文案必须短且单行。
- 不使用 emoji 作为功能图标；优先使用项目资产中的 SVG 图标或文本标签。

## Token 约束

- 前端实现优先消费语义变量：`--background`、`--foreground`、`--card`、`--muted-foreground`、`--primary`、`--border`、`--input`、`--ring`。
- 圆角使用：`--radius-sm`、`--radius-md`、`--radius-lg`、`--radius`。
- 阴影使用：`--shadow-sm`、`--shadow-md`、`--shadow-lg`，普通静态卡片优先 `--shadow-sm` 或无阴影。
- 状态色只用于真实状态：`--success`、`--destructive`；不要为分类、人物或生活主题创造多套颜色。
- 新增 CSS 不应硬编码颜色值；若必须扩展 token，先在设计规范中说明角色和使用边界。

## 组件规范

- `Navigation`：固定四个核心目的地“工作台、记录、进展、系统”；避免把工具入口塞进导航。
- `Card`：标题短、正文克制；卡片之间用网格和留白分组，不靠粗分割线。
- `Button`：主按钮为蓝色胶囊；次按钮优先文字或浅灰胶囊；危险操作必须先出现确认态。
- `Input`：记录输入区要大、安静、低压力；placeholder 鼓励“一句话也可以”。
- `Comparison / Table`：只展示对判断有帮助的字段；缺失值必须明确标记，不能推断补齐。

## UE 原则

- 记录优先：用户可以直接输入自然语言；表单只在对话不便时使用。
- 未记录不等于跳过：未知、跳过、最低版、完成必须视觉和语义分离。
- 本地成功先完成：保存到 iCloud 成功即可回执；外部展示失败不得回滚本地结果。
- 冲突不覆盖：revision 冲突时展示当前值与本次提交，让用户选择使用最新记录或重新提交。
- 删除要有边界：删除提示必须说明不影响聊天、旧备份与设备历史等不在范围内的副本。

## 文案规范

- 使用中文，短句优先。
- 标题应像产品标语一样克制，例如“今天，只看必要信息”“记录，不打断生活”“趋势，只是辅助判断”。
- 避免“必须、失败、落后、坚持打卡”等压力词；优先使用“可以不做、稍后再说、保持未知”。
- 不把趋势、睡眠或步数描述成医学、人格或长期能力结论。

## 隐私与数据边界

- 原型、截图、测试 fixture 和规范文档不得包含真实日记原文、健康明细、外部服务标识、凭据或个人长期记忆。
- UI 示例只展示摘要、状态与合成样例。
- 浏览器本地存储不得成为个人数据真相源；网页只显示后端白名单投影。
- 任何公开部署、共享链接或外部同步都必须经过当次明确确认。

## 与现有前端的衔接

- 当前 React 页面可继续保留四页结构：`TodayPage`、`RecordsPage`、`ProgressPage`、`SystemPage`。
- 重构优先顺序：先抽象 `AppShell` 与 token，再改造 `TodayPage` 和 `RecordsPage`，最后统一图表和系统页状态卡。
- 每次前端变更都要维护本规范；若实现因工程约束偏离设计，记录偏离原因和恢复条件。
