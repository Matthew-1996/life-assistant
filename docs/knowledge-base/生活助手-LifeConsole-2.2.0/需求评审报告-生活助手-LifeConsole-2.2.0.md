# 需求评审报告 - 生活助手 - Life Console - 2.2.0

> 状态：Gate 1 已由 PO 确认
> 评审结论：有条件通过

## 1. 评审范围

评审 Vercel + Supabase 是否适合作为 Life Console 下一阶段在线架构，以及登录、数据边界、备份与迁移范围是否合理。本评审不等于开发、资源创建或上线授权。

## 2. 多角色结论

| 角色 | 结论 | 核心意见 |
|---|---|---|
| PO | 待确认 | 需要确认 D1-D8，尤其是登录方式、敏感字段加密和未来迁移顺序 |
| PMO | 有条件通过 | 先完成双 Gate，再按每块不超过 4 小时推进，保持唯一分支和单一前端 |
| 设计师 | 通过 | 复用已验收四页；新增登录、同步和冲突状态，不新增“迁移中心” |
| 前端 | 通过 | React/Vite 可接 `supabase-js`；需调整 CSP、会话态和 API 适配层 |
| 后端 | 有条件通过 | Postgres + RLS 适合结构化私人数据；权限、幂等、修订和备份必须先于真实数据 |
| QA | 有条件通过 | 必须有第二个合成用户验证越权拒绝，不能只验证未登录 401 |
| 数据仓库 | 通过 | 首版不建数仓；分析指标只来自业务表的去敏聚合，不复制个人原文 |
| 安全/隐私 | 有条件通过 | publishable key 可在前端，secret/service-role 只在服务端；真实敏感数据需另做威胁模型 |

## 3. 方案合理性与成本

| 维度 | 评估 | 说明 |
|---|---|---|
| 用户价值 | 高 | 解决跨设备访问与本地服务依赖，延续当前移动端入口 |
| 产品连续性 | 高 | 复用 2.1.0 页面与备份减法，不再建设第二前端 |
| 技术可行性 | 中高 | Auth、Postgres、Data API、RLS 能覆盖核心 CRUD；备份和字段加密仍需 POC |
| 隐私风险 | 中高 | 个人日记与健康数据上云扩大暴露面，必须先合成验证并设置独立真实数据门禁 |
| 开发成本 | 中 | 可复用现有 React、契约和测试；需重写 Sites 专用适配层及数据模型 |
| 运维成本 | 中 | Vercel + Supabase 两个平台可维护，但环境、密钥、备份和配额需持续检查 |

## 4. 主要风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| RLS 漏配导致跨用户读取 | 高 | 所有暴露表默认拒绝，显式 GRANT + RLS；Owner/非 Owner/anon 自动测试 |
| 前端泄露高权限密钥 | 高 | 浏览器只使用 publishable key；secret/service-role 不进入 Vite 变量、Git 或日志 |
| 邮件登录允许陌生账号注册 | 高 | `shouldCreateUser=false`，测试环境只邀请合成账号；Owner 识别不依赖可编辑的 user metadata |
| 写入冲突或重复 | 高 | revision/etag、`If-Match` 语义、唯一幂等键和原子 upsert |
| 云端成为唯一数据副本 | 高 | 版本化 iCloud 最新备份 + 合成恢复演练；平台备份不替代用户可迁移备份 |
| 免费/低配套餐暂停或备份不足 | 中 | 建项前确认套餐；免费方案定期逻辑导出，付费备份/PITR 仅作附加防线 |
| 双平台配置漂移 | 中 | Preview/Production 分离、环境清单、可重复检查；不把环境值写入仓库 |
| 旧 Sites 能力继续并行污染 | 中 | 2.2.0 停止投入旧路线；任何资源处置另开门禁 |

## 5. Gate 1 结论

PO 已于 2026-08-12 确认 PRD draft.1、D1-D8，并接受“有条件通过”的评审结论。设计、技术和测试方案进入 Gate 2 定稿；本确认不授权资源创建、实现、部署、真实数据、切源、删除或合并。
