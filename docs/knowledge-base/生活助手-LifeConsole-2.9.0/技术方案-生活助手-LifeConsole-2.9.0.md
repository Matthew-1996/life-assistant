# 技术方案

## 入口兼容

新增服务器构建变量 `LIFE_CONSOLE_SELF_HOSTED_ORIGIN`，与 `VITE_SUPABASE_URL` 的规范化 HTTPS origin 精确一致。拒绝用户信息、路径、查询、片段和通配符；允许明确配置的端口。未设置时保留现有托管域名限制。

CSP 仅加入一个已确认的 HTTPS origin；自托管路线未启用 Realtime，不添加 WSS 来源。现有 Production 项目名、域名、密钥隔离及 Cron 守卫保持有效。

自托管公开凭据必须是 `role=anon` 的传统 JWT；构建时检查结构和角色，服务端继续负责签名验证。禁止将 service-role JWT 或服务器管理凭据用作浏览器公开配置。

生产配置提供 `LIFE_CONSOLE_NEWS_SCHEDULE=daily|disabled`：默认保留每日计划，显式 `disabled` 生成空 Cron 列表。迁移部署按已核对的线上状态禁用调度，避免因重新发布而恢复搁置任务；无效值使构建配置生成失败。

## 数据与认证

目标为兼容 PostgreSQL、Auth 与 PostgREST 的后端。迁移须保存真实 schema、函数、授权、RLS、序列及 Owner 身份引用。不同实例的登录会话不可默认复用；须验证新登录和刷新路径。

按源库元数据与完整备份制作迁移清单，不能只运行本地历史迁移文件后宣称等价。所有凭据、真实数据和服务绑定保留在私有运行环境，Git 只保存通用代码与去敏证据。

## 切换和回退

冻结所有活跃写入方，最终导出，核对计数与内容摘要，执行候选验收后统一切换客户端与任务。旧源保留为回滚锚点；新源发生写入后，回退先迁回差异，禁止直接切回旧库造成数据丢失。

## 2026-09-28 账户恢复范围调整

现阶段仅保留已有邮箱账号和密码登录，默认关闭邮件找回入口。忘记密码时由本人在后台手动重置，前台显示“忘记密码请联系管理员重置。”；旧恢复路径返回登录。保留现有账户身份和密码，不开放注册或公网管理接口。管理员工具与部署说明由独立私有后端项目管理，SMTP 不再作为发布前提。真实迁移和生产验收仍单独跟踪。
