# 设计方案：Life Console 2.4.0

## 1. 信息架构

日记卡片只有一种结构：

1. 日期、时间精度与标题
2. 来源、隐私和标签
3. 用户原话
4. 助手整理
5. 整理状态与可用动作

“助手整理”固定顺序为摘要、明确事实、明确感受、人物、地点或场景、生活主题、可能的规划线索、待用户确认的推测。空字段显示“未记录”，不隐藏字段导致用户误以为入口不同。

## 2. 状态设计

| 状态 | 用户文案 | 动作 |
|---|---|---|
| `pending` | 已保存，等待整理 | 可继续浏览 |
| `processing` | 正在整理 | 不重复发起 |
| `completed` | 已完成助手整理 | 查看完整字段 |
| `failed` | 原文已保存，整理暂未完成 | 重试整理 |
| `stale` | 原文已更正，需要重新整理 | 重新整理 |

任何状态都不得把“整理失败”显示成“日记未保存”。

## 3. 人物关系展示

- 原文明示：“朋友小林” → 展示“小林（朋友）”，依据为原文。
- 原文只写关系称谓，但获批人物字典存在唯一映射 → 可展示规范姓名、别名和关系，依据为已确认个人档案。
- 映射缺失或有多个候选 → 保留原称谓，不猜姓名。
- 前端不展示内部 profile ID，只展示用户可理解的依据提示。

## 4. 编辑与修订

- 原文更正产生新 revision，原结构化结果进入 `stale`，不会继续冒充当前事实。
- 用户可以修订助手整理；人工修订标记为 `user_edited`，后续自动重试不得覆盖。
- 单纯重试同一原文 revision 使用同一整理任务键，不产生多份结果。

## 5. 降级

- Agent 不可用时，Agent 入口不静默改用外部模型；先明确原文已保存、整理待完成。
- 网页入口只有在 PO 授权 DeepSeek 数据处理后才自动兜底。
- DeepSeek 不可用、余额不足、返回空内容或 Schema 不合法时，原文保持可见，错误只显示通用原因。
