# 工程评审与验收 - 生活助手 - Life Console - 1.0.0

> 状态：已建立可重复验收基线
>
> 适用范围：通用仓库代码、规则、设计和知识库；真实个人数据只在 iCloud 私有环境做一致性验收。

## 1. 技术评审结论

| 评审项 | 当前结论 | 持续门禁 |
|---|---|---|
| 架构 | 本地优先模块化单体符合 1.0.0 范围 | 不引入第二真相源或远程个人数据 API |
| 前后端契约 | OpenAPI 是接口与生成类型的唯一来源 | 契约生成结果必须无漂移 |
| 数据一致性 | 锁、revision/etag、来源哈希和原子替换覆盖主要写入 | 新写入必须补同域并发与漂移测试 |
| 隐私 | Git、localhost、严格字段和外发授权形成分层防线 | 索引与分支历史检查均通过 |
| 展示层 | Life Console 主入口；Google/XLSX 按需；网页归档 | 生命周期清单必须保持规范状态 |
| 可恢复性 | 私有完整备份与 Git 历史分别承担数据和代码恢复 | 备份必须独立校验，缓存不视为备份 |

本结论不承诺未来提交自动符合要求，也不使用固定日期的隐私评级、旧提交号或测试数量证明当前状态。每次合入以本文件的可重复检查为准。

## 2. 测试方案

### 2.1 静态与治理检查

```bash
python3 tools/check_project_governance.py
python3 tools/validate_project.py
tools/check_git_privacy.sh
tools/check_git_privacy.sh --history origin/main..HEAD
git diff --check
```

覆盖唯一规范正文、知识库六类文档、展示生命周期、设计资产、禁止路径、凭据与机器路径。Git 历史检查不能被“当前索引已删除”替代。

### 2.2 通用工具测试

```bash
python3 -m unittest discover -s tools -p 'test_*.py'
node --test tools/test_life_plan_records.mjs tools/test_google_sheets_payload.mjs
```

重点覆盖严格 Schema、幂等、并发冲突、原子替换、删除计划、中断恢复、日记双向完整性、备份源漂移、展示生命周期和安全输出。

### 2.3 Life Console

```bash
cd apps/life-console
npm ci
npm test
npm run build
```

`npm test` 包含契约生成检查、前端与隐私 Fixture 测试、Python Hub/安全/打包测试及合成 E2E。构建和合成测试通过不代表某台机器的 iCloud 已获得读写权限；真实运行状态必须单独验收。

## 3. 联调与真实环境验收

在用户授权的私有 iCloud 项目中，用最小、可恢复的测试记录完成以下链路：

1. Life Console 获取本地 session，读取 Dashboard 白名单投影。
2. 通过固定适配器执行一次幂等写入并读回相同事实。
3. 验证 revision 冲突不会覆盖较新数据。
4. 撤回测试记录，并运行日记/台账完整性检查。
5. 验证 Google 与 XLSX 只有在明确按需触发时生成，且不反向写回。
6. 确认归档 Life Dashboard 没有新构建或部署；既有实例的访问范围只做读回检查。

只有真实读、写、读回、撤回和完整性检查均通过，运行时才可以报告 iCloud `writable`。任何个人内容、服务标识或本机路径不复制到 Git 证据中。

## 4. 上线与合入证据

每个最终 PR 至少记录：变更范围、用户门禁状态、知识库更新、隐私检查、Python/Node/Life Console 结果、未覆盖边界。CI 只证明该提交的通用检查；外部发布、真实数据迁移、永久删除和用户验收仍需独立证据与授权。

不可变历史证据保留在 `research/`，用于回答“当时验证了什么”；当前方案与操作方法只在本版本知识库、源码、契约和测试中维护。历史证据与当前实现冲突时，以重新运行当前检查并完成必要评审为准。
