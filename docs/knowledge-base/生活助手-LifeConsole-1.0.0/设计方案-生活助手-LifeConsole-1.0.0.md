# 设计方案 - 生活助手 - Life Console - 1.0.0

> 状态：已确认的 1.0.0 设计基线
>
> 产品需求：[生活助手-LifeConsole-1.0.0.md](生活助手-LifeConsole-1.0.0.md)
>
> 当前设计资产：[UI 设计治理](../../design/README.md)

## 1. 设计目标

Life Console 是 Mac-first 的本地生活工作台。它把分散的生活记录、当前行动和系统状态压缩成可快速理解的界面，但不制造新的打卡压力，也不取代对话式生活助手。

设计优先级依次为：降低认知负担、保留用户控制感、守住 iCloud 真相源边界、在异常时明确失败而不猜测。页面不使用竞争、惩罚、连续打卡或无依据的健康结论推动行动。

## 2. 产品信息架构

| 页面 | 用户问题 | 核心内容 | 允许的主要动作 |
|---|---|---|---|
| 工作台 | 今天最重要的是什么 | 当前焦点、生活锚点、阶段进度、必要提醒 | 刷新、选择一个低负担动作 |
| 记录 | 我刚刚想留下什么 | 日记入口、每日状态、最近记录与整理状态 | 新增、确认、处理冲突 |
| 进展 | 最近发生了什么变化 | 自然周趋势、明确事实、待确认线索 | 查看，不自动下结论 |
| 系统 | 数据和能力是否可靠 | 本机 Hub、iCloud、自动化、备份、派生展示 | 查看状态、进入明确维护动作 |

导航固定为这四个一级入口。新增模块优先放入已有页面的次级区域；只有用户任务无法被现有信息架构清楚承载时，才经新版本需求与设计评审增加一级入口。

## 3. 关键交互原则

### 3.1 写入与确认

- 普通新增通过受控表单或对话进入本地原子工具；UI 不直接编辑真相源文件。
- 冲突、永久删除、外部发送和长期认识写入采用预览或精确确认，不用模糊的“继续”代替审批。
- 本地写入成功但只读投影刷新失败时，明确显示 `pending_refresh`；不重复写入、不回滚已成功的真相源。

### 3.2 信息密度与反馈

- 首屏只显示对当前决定有帮助的信息；细节按需展开。
- 未知值保持未知，不用默认值、设备数据或平均值补齐用户没有表达的主观状态。
- 趋势用于帮助回顾，不把短期波动包装成稳定结论或诊断。
- 错误提示说明当前影响与安全下一步，不显示原始日记、个人路径、凭据或内部堆栈。

### 3.3 响应与无障碍

- 所有关键状态同时使用文字与形状表达，不能只依赖颜色。
- 键盘焦点、控件标签、确认范围与可撤回边界必须可见。
- Mac 桌面是 1.0.0 的主要环境；不把页面强行缩放成新的移动端产品。

## 4. 视觉系统

唯一视觉系统位于 [`docs/design/apple-top-level-design-system/`](../../design/apple-top-level-design-system/)。当前约束包括：克制留白、轻边框卡片、胶囊动作、黑白灰主色、蓝色只用于关键强调，以及 DM Sans / JetBrains Mono 的排版分工。

视觉 token、组件规范和组件预览由顶层设计系统维护；产品文案、交互语义和隐私边界由 [`life-console-apple-ui-ue-guidelines.md`](../../design/life-console-apple-ui-ue-guidelines.md) 维护。两者不复制到 React 源码说明中。

## 5. 当前交互稿

唯一当前原型为 [`life-console-trial-week-redesign/`](../../design/life-console-trial-week-redesign/)，包含工作台、记录、进展、系统四页静态稿。它定义信息层级与交互意图；React 实现、OpenAPI 和本地安全限制定义可运行边界。两者不一致时，PR 必须说明差异并选择更新实现或更新原型，不能长期保留两个“当前版本”。

上一版 Life Console 原型和根目录设计导出不再留在活动树；需要审计时从 Git 历史读取。

## 6. 展示层关系

展示生命周期以 [`docs/operations/product-surfaces.json`](../../operations/product-surfaces.json) 为准：Life Console 是主要入口；Google 表格与 XLSX 只按需派生；Life Dashboard 已归档且不得继续部署。任何展示层都不得反向覆盖 iCloud 真相源。

## 7. 设计变更门禁

- 修改视觉 token 或通用组件：更新顶层设计系统并说明对当前原型和 React 的影响。
- 修改页面结构、主要任务或一级导航：先更新当前原型，并判断是否需要新产品版本。
- 修改写入、删除、外发或隐私语义：同步更新 PRD、技术方案和验收用例，取得对应 PO 门禁。
- 仅修复实现偏差且不改变产品行为：可走快速维护通道，但仍需测试与差异说明。
