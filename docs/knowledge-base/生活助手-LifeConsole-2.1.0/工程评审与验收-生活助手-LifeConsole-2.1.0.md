## 3. Gate 2 后第一工作块：回环 POC

POC 只使用合成文本和临时目录，不绑定真实 D1、R2、KEK 或 iCloud。

### POC-01 浏览器连接

- HTTPS 测试页访问回环 `/v1/health`。
- 记录是否出现本地网络权限提示、CORS 预检及用户拒绝后的错误形态。
- 当前 ChatGPT in-app Browser 与 Chrome 分别记录；Safari 只观察，不作为首版通过条件。

### POC-02 安全边界

- 非白名单 Origin 预检失败。
- 缺失自定义意图 Header、错误 Content-Type、重定向、局域网绑定全部拒绝。
- 代理端口只监听 `127.0.0.1`，不监听 `0.0.0.0`。
- 不存在任意文件读取、目录浏览或命令执行路由。

### POC-03 合成传输

- 传输合成 ZIP，代理写入临时目录并返回去敏回执。
- 页面关闭、代理中断和重复请求不产生部分正式文件。
- POC 通过后才允许开始 W3/W4 实现；失败则回到 Gate 2 重新选型。

### 2026-08-11 阶段 A 实测记录

| 项目 | 结果 | 去敏证据与结论 |
|---|---|---|
| 回环服务安全边界 | 通过 | 4 项 Python 合成单测通过：Origin SHA-256 白名单、CORS/LNA 预检、自定义意图 Header、Content-Type、IPv4 loopback 绑定和合成 ZIP 原子写入；仅使用临时目录 |
| 当前正式 HTTPS 页面实际跨 Origin 请求 | 未通过 / 阻塞 | 当前已部署版本的 CSP 仍是 `connect-src 'self'`，且本轮禁止正式部署；浏览器自动化的只读页面上下文也不提供 `fetch`，因此不能把实际 HTTPS → localhost/LNA 兼容性冒充为已验证 |
| 下一候选源码准备 | 通过 | 未部署源码已将 CSP 最小放行固定回环端口；仍需后续单独取得候选部署授权后，在真实页面验证权限提示、拒绝形态与预检 |
| S 容量档 | 本地算法通过 | 约 1.05 MB 合成 NDJSON，归档约 1.05 MB，约 42 ms，进程 RSS 增量约 13.9 MB |
| M 容量档 | 本地算法通过 | 约 4.19 MB 合成 NDJSON，归档约 4.19 MB，约 180 ms，进程 RSS 增量约 23.1 MB |
| L 容量档 | 本地算法通过 | 约 8.39 MB 合成 NDJSON，归档约 8.39 MB，约 418 ms，进程 RSS 增量约 66.1 MB |
| Worker 平台容量 | 延期 | 上述仅证明同一 ZIP 算法在本机 Node 进程可运行，不等于 Sites Worker 的真实时间/内存上限；本轮无部署授权，不声称平台容量通过 |

阶段 A 总结：**条件未通过**。安全边界与本地容量 POC 可继续保留，但正式 HTTPS 页面回环与 Worker 平台容量仍缺实际候选环境证据。依照 Gate 2 的“先 POC、后实现”，阶段 B-E 暂不启动；正式环境、真实数据和云资源均未触碰。

## 4. Worker 与 D1 测试用例

| ID | 用例 | 通过标准 |
|---|---|---|
| WK-01 | 创建备份运行 | 仅 Owner + CSRF 可创建；初始 `CREATED` |
| WK-02 | 非 Owner / 未登录 | 分别按实际身份门禁返回拒绝；不把 401 冒充 403 |
| WK-03 | 一致导出 | 各个人资源数量、ID、revision 和摘要与合成源一致 |
| WK-04 | 敏感字段解密 | ZIP 内是规范化恢复字段；D1 仍存密文 |
| WK-05 | 排除运维数据 | ZIP 不含 audit、idempotency、backup_runs、会话和 hash |
| WK-06 | 写入锁 | 导出期间写请求返回 `423 backup_in_progress`，读取仍可用 |
| WK-07 | 锁超时 | 异常后 TTL 释放，不造成永久只读 |
| WK-08 | 状态转换 | 只允许定义的顺序；非法 complete/fail 返回冲突 |
| WK-09 | 去敏失败 | `error_code` 仅固定枚举，不保存异常正文 |
| WK-10 | 审计最小化 | 记录 backup 动作与结果，不含 ZIP、正文、查询参数 |
| WK-11 | R2 独立 | 新备份链路在无 R2 binding 时仍完整通过 |
| WK-12 | 恢复包路由移除 | 三个恢复包路由不可用，契约与前端均无引用 |

## 6. 本机代理原子性与安全测试

| ID | 用例 | 通过标准 |
|---|---|---|
| LA-01 | 首次成功 | 生成唯一最新 ZIP，文件权限 `0600`，父目录收敛 |
| LA-02 | 成功覆盖 | 新包校验通过后原子替换；最终只保留一份稳定备份 |
| LA-03 | 写入中断 | 临时文件清理，旧备份字节完全不变 |
| LA-04 | 空间不足 | 返回固定错误码，旧备份不变 |
| LA-05 | 摘要错误 | 拒绝替换，旧备份不变 |
| LA-06 | ZIP Slip | 绝对路径、`..`、符号链接、重复路径全部拒绝 |
| LA-07 | Zip bomb | 文件数、单文件、总解压大小和压缩比超限时拒绝 |
| LA-08 | 非法 Origin | 不返回 CORS 授权，不写临时文件 |
| LA-09 | 并发请求 | 只允许一个运行；第二个返回忙碌，不互相覆盖 |
| LA-10 | 重复运行 ID | 幂等返回既有回执，不重复替换 |
| LA-11 | 回执补报 | 页面关闭后只保留去敏回执；补报后可删除 |
| LA-12 | 日志扫描 | 不出现个人正文、ZIP、完整摘要、凭据或机器路径 |

## 8. 合成 E2E 主链路

```mermaid
flowchart LR
    A[合成 D1 + 合成 KEK] --> B[Owner 浏览器创建备份]
    B --> C[Worker 生成规范化 ZIP]
    C --> D[浏览器转发到回环代理]
    D --> E[临时目录原子替换]
    E --> F[代理读回校验]
    F --> G[浏览器回报 SUCCESS]
    G --> H[系统页显示最近成功]
```

必须增加三个故障 E2E：

1. 传输 50% 时终止代理，旧备份不变。
2. 代理写成功后阻断云端回报，下次打开页面补报成功。
3. 导出期间模拟写请求，前端保留草稿并在备份结束后可重试。

## 9. 性能与容量门槛

Gate 2 后用纯合成数据建立三个档位，数量不映射真实用户数据：

| 档位 | 用途 | 门槛 |
|---|---|---|
| S | CI 日常 | 全链路快速完成 |
| M | 预估日常上限的合成档 | Worker 不超时、不超内存，浏览器无明显卡死 |
| L | M 的 2 倍 | 用于决定单请求 ZIP 是否可实施 |

若 L 档失败或接近平台限制，技术结论变为阻塞：停止实现单请求方案，重新设计版本化分块和一致性，不以降低测试规模掩盖风险。
