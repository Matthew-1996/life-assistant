# 设计方案 · Life Console 2.10.0

## 视觉与结构

沿用现有苹果式白、灰、蓝体系，系统字体、16px 卡片圆角、浅边框和克制阴影。工作台顺序为每周寄语、原有 Todo/资讯区域、健身计划、今日锚点。原型顶部和相邻模块只提供上下文，不模拟原产品所有功能。

桌面主内容宽约 1180px。模块标题行左侧为“健身计划”，右侧唯一主操作“新增预约”。次行提供月份前后切换、今天与 Apple 日历订阅。主体左侧月历约 2/3，右侧日详情约 1/3。

今天以小蓝点提示；选中日用浅蓝底与蓝色日期标识，两者语义分开。非当月日期弱化。预约不按训练种类编码彩色或引入完成状态。日详情完整显示起止时间、标题、地点和保留换行的备注；长文本换行，不突破卡片。

## 原型

[打开唯一交互设计稿](../../design/life-console-fitness-plan.html)。合成月份按上海时区当前日期初始化；示例预约落在今天、明天及后续日期。不会保存或连接真实服务，刷新恢复示例。

评审工具条与产品界面分离，可切换正常、空日历、下次保存失败、下次版本冲突；可恢复示例。工具条不是未来产品功能。

## 编辑与异常

- 新增和编辑共用右侧模态面板，使用原生 dialog 提供键盘与 Esc 交互；取消返回触发入口，保存/删除后回到稳定的“新增预约”按钮。原生焦点约束与回焦尚待浏览器验证。
- 标题、日期、开始和结束时间必填；空地点显示“地点待定”，备注为空时不虚构内容。
- 改期成功后跳转到新日期；取消不改变预约。重叠提示允许继续保存。
- 保存失败：保留输入，显示“未保存”，允许重试或放弃，不出现成功状态。
- 版本冲突：并排呈现当前版本与本次输入，禁止直接覆盖；用户加载最新版本后再编辑、保存。
- 删除确认说明将从站内安排移除；已启用订阅时 Apple 端须等待刷新，不能声称立即消失。

## 订阅设置

初态“未启用”；说明单向、延迟、私密链接持有者可读。默认输出事件、起止时间和地点，备注勾选默认关闭。

原型“模拟启用订阅”只演示状态；不生成可用 URL、不打开 Apple 日历，不申请任何账户权限。启用后可演示停用和更换链接；更换提示需重新订阅。真实产品的链接展示仅在认证后的明确操作中出现。

不能读取 Apple 客户端的实际刷新回执，因此不展示“Apple 已同步”或未经证实的同步时间。

## 适配边界

本轮只产出一份桌面 HTML，不生成移动端设计稿、PNG 或 SVG 文件。后续产品实现仍需保证原有手机工作台可用，可将月历和详情纵向排列；本轮不以移动端为已验收范围。
