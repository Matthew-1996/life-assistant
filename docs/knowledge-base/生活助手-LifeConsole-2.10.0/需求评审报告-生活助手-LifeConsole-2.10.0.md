# 需求评审 · Life Console 2.10.0

## 结论

按已确认范围开展设计合理；站内预约模块可复用当前认证、版本冲突和工作台容器。Apple 单向订阅具备官方能力依据，但本项目端到端可靠性尚未验证，不能标记为已支持。

## 角色视角评估

以下为同一 Agent 的多角色分析，不代表独立人员或独立 Agent 已完成评审。

| 视角 | 判断 |
|---|---|
| PO | 已选择月历＋当日详情、时间不固定、无完成状态、单向订阅；新增交互细节待本稿评审 |
| PMO | 独立功能版本 2.10.0；本轮止于设计交付，后续实现、验收、上线分开 |
| 设计 | 工作台内全宽卡片适合月历与日详情并列；保留现有视觉语言 |
| 前端 | 独立预约组件、日历投影和 repository 接口，避免将 Todo 状态带入预约 |
| 后端 | Owner-scoped 新表与原子 RPC 可复用现有模式；订阅需独立受控读取接口 |
| QA | 重点关注跨月日期、改期后选中日、冲突、失败草稿、ICS 稳定标识与删除收敛 |
| 数仓 | 不需要数据仓库、训练统计或跨层汇总 |

## 取舍

采用单向订阅，避免双端编辑冲突与 Apple 凭据托管。仅导出文件无法自动更新，不作为订阅的替代承诺。若订阅探针不通过，先完成站内日历，订阅功能暂缓且默认关闭。

工作块 A（不超过 4 小时）：方案、官方资料核查、评审草案。工作块 B（不超过 4 小时）：本地合成设计稿、交互验证。主项为预约管理设计；次项为订阅设计；真实同步验证可延后。
