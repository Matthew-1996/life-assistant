# PRD：Life Console 2.5.0

状态：Gate 1 与 Gate 2 v2 已确认；按批准方案进入 TDD 开发。

## 1. 背景与目标

2.4.0 已建立 Owner 登录、Supabase 唯一真相源、日记统一整理和 Production 严格 CSP 基线。2.5.0 不再扩展底层个人数据范围，重点解决页面信息重复、日记与复盘可读性、近期状态趋势缺失，以及高优事项和公开新闻缺少统一入口的问题。

成功目标：

1. 工作台在一个首屏内提供寄语、Todo、每日新闻和今日锚点。
2. 记录页只保留对话式记录、日记与修订、复盘，减少重复入口。
3. 进展页只保留目标、14 天趋势和 7 天睡眠时刻。
4. 所有新增私人数据继续由 Owner-scoped Supabase 管理；新闻为可重建公开缓存。
5. 390px 与 1440px 页面无横向溢出，严格 CSP 不退让。

## 2. 信息架构

| 页面 | 2.5.0 保留或新增 | 移除 |
|---|---|---|
| 工作台 | 每周寄语、Todo 列表与甘特、每日新闻、2.4.0 四项今日锚点 | 生产环境说明、待确认、今天可以不做、隐私与保存链路 |
| 记录 | 对话式记录、线上日记与修订、周/阶段复盘 | 写入语义、原文保存预览、简洁表单兜底、已录入与上下文 |
| 进展 | 目标、14 天主观/健康趋势、7 天入睡/醒来/离床 | 自然周进展、复盘边界及重复解释 |
| 系统 | 保持现有行为，仅更新版本说明 | 不新增功能 |

全局顶部删除“Life Console · Supabase 唯一真相源 · iCloud 单向备份”横幅；真相源和备份事实继续保留在系统与文档中。

## 3. Todo

- 字段：展示序号、标题、优先级 `P0 | P1 | P2`、状态 `未开始 | 进行中 | 已完成`、计划开始时间、DDL、实际开始时间、实际完成时间、revision。
- 新建默认 P1、未开始；计划开始默认当前时间但可改；DDL 必填且必须晚于计划开始。
- 状态首次进入进行中时由数据库写入实际开始时间；首次进入已完成时写入实际完成时间；退回前一状态时对应后继时间清空并记录事件。
- 允许任意状态间显式切换：未开始直接完成时，实际开始和完成时间取同一事务时间；已完成退回进行中时保留实际开始并清空完成时间；退回未开始时清空两者。重复提交当前状态不增加 revision 或事件。
- 逾期是 `未完成且 DDL < 当前时间` 的派生展示，不自动修改 DDL。
- “今日”展示已经开始的开放项，以及本地自然日内完成的项目；“全部”展示未来项目。
- 默认排序：P0 → P1 → P2、DDL 升序、创建时间升序；序号按当前筛选结果生成，不持久化。
- 甘特默认展示以今天为中心的 14 天窗口，可横向滚动；计划条与实际完成标记分层显示。
- 每条 Todo 提供删除入口并二次确认；删除只设置 `deleted_at`、增加 revision 并写入审计事件，活动列表与甘特固定排除已删除项。2.5.0 不提供 Todo 永久删除或恢复界面。

## 4. 今日锚点

- 复用现有 `起床`、`身体 / 光照`、`生活动作`、`晚间降速` 和 `daily_checkins.anchors` 数据，不新增表或从 Todo 推导。
- 每项显示 `未填写 | 完成 | 最低版 | 跳过`；未填写保持未知，不计为失败或跳过。用户可以把已填写项修改为另一个可写状态。
- 区块显示非空状态数量，例如 `3 / 4 已填写`；状态保存继续使用既有 revision 冲突保护、保存中/成功/失败和未保存草稿语义。

## 5. 记录与复盘

- 页面头部不显示“写入语义 / 草稿不会自动生效”卡片；内容按对话式记录 → 日记记录 → 复盘排列。
- 日记卡默认只展示标题、日期和用户原话；助手整理、标签和修订记录折叠。
- 日记支持编辑日期、标题、原文和标签；编辑及删除不得放入另一套重复入口。
- 删除必须二次确认，执行 `deleted_at` 软删除；已删除列表提供恢复，不提供永久删除。
- 周复盘与阶段复盘优先把已知 `structured_data` 字段转换为中文标签；未知对象按自动换行纯文本展示。
- 复盘内容最大高度 320px，超出后在卡片内部滚动，不得撑破页面。

## 6. 进展

- 14 天窗口包含最近 7 天和前 7 天，按同一指标比较均值或日级总量。
- 主观信号沿用显式填写的 1–5 评分；未填写保持未知，不从日记、设备或均值推断。
- Apple Health 仅展示步数、活动能量、锻炼分钟、睡眠时长；不增加心率或 HRV。
- 任一 7 天窗口有效样本少于 3 时显示“数据不足”；分析只使用上升、下降、稳定和缺失，不作诊断。
- 睡眠时刻表只展示最近 7 天的入睡、醒来、离床；缺失字段显示“未记录”。

## 7. 每周寄语

- 每周一 12:00 Asia/Shanghai 生成一条寄语，整周复用；“每日寄语”是展示名称，不代表每天重新生成。
- 只读取活跃目标、未完成 P0/P1 Todo 和最近一条周复盘；不读取日记原文、健康明细或阶段复盘。
- 默认原创短句；可使用有可靠出处的公版短引文。只保存最终寄语与展示元数据，不保存输入副本。
- Unsplash 查询只使用通用主题词；按官方要求热链并展示摄影师与平台归因。无 Key 或请求失败时使用内置渐变。

## 8. 每日新闻

- 每日 07:00 Asia/Shanghai 生成科技、财经、政治相关的国内外 Top 5 摘要。
- GDELT 是过去 24 小时候选发现主源；若请求失败、超时、限流或无法形成规定配比，切换到无需新密钥的官方公开备用源。国内使用新华网当前科技、财经、时政频道页面，国际使用 BBC Technology、Business、World RSS；已停更的新华网旧 RSS 不进入运行链路。
- 主源与备用源都只能产生可信域名内的公开标题、链接、发布时间、片段和页面描述；每个备用入口独立失败隔离、设置超时和响应体上限，不抓取或保存新闻全文。
- 去重后科技、财经、政治至少各 1 条，同时至少包含国内和国际各 1 条；剩余名额按当日重要性分配。
- DeepSeek 只接收公开标题、发布时间、候选发现片段和公开页面描述。每条摘要不超过 160 个中文字符；缺失的时间、地点、人物、原因、经过或结果保持未知。
- 当日结果和最近成功版本最多保留 7 天。外部服务失败时显示上一成功版本和更新时间；完全无缓存时显示可重试空态。
- 每次通过鉴权的 Cron 调用保存最近 7 天的去敏运行记录：开始/结束时间、结果状态、候选来源、失败阶段和稳定错误码。运行记录不含新闻正文、模型输入、Secret、Owner 标识或私人数据，并通过 Owner 鉴权接口只读查询。
- 运行记录使用现有同区域 Vercel Runtime Cache，属于可跨部署读取但可能被平台逐出的运维记录，不作为永久审计台账；本次不新增 Supabase 表、服务器级 Supabase 密钥或备份资源。

## 9. 非目标

- 不提供 Todo 自动延后 DDL、原生日历同步、复杂依赖关系、永久删除或恢复界面。
- 不提供日记永久删除、历史批量重写或新闻全文保存。
- 不新增心率、HRV、医疗判断或模型生成健康结论。
- 不改变系统页能力，不恢复已归档的 Life Dashboard。

## 10. 成功标准

- 所有 PRD 指定区块确实移除，四页导航与 Owner 登录不回归。
- Todo 创建、编辑、状态流转、软删除、逾期、排序与甘特符合定义，数据库时间原子一致。
- 今日锚点四项沿用 2.4.0 语义，可显示填写进展并修改；中等桌面双栏放不下时改为上下布局，页面无横向溢出。
- 日记删除可恢复；复盘长文本可读；趋势缺失语义准确。
- 纯合成 Preview 显示合成日记的标题和原文，可演示编辑、软删除和恢复；操作只在当前页面内存中生效，刷新后重置且不读写 Owner 数据。
- GDELT 不可用时，受信任备用源可独立形成完整 Top 5；若所有公开源仍不足，则安全降级且不伪造摘要。
- 新闻和寄语在外部服务失败时安全降级，不暴露 Secret 或私人输入；Owner 可以查询最近 7 天的去敏 Cron 运行结果。
- 全量治理、隐私、数据库、Vitest、Python、build、Playwright 和 Production 浏览器门禁通过。
