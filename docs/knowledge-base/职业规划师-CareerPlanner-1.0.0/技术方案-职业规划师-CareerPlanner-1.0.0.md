# 存储与维护方案：职业规划师 Career Planner 1.0.0

> 状态：Gate 2 已确认；本地文件方案已实现并通过合成验收。本方案明确不建设 App、前端、后端、API、数据库或云端服务。

## 1. 方案概览

职业规划师只有两部分：

1. 由生活助手执行的专业职业咨询规则；
2. 用户可直接打开查看的 iCloud 本地职业文件夹。

```text
用户对话 / 工作日提醒
          │
          ▼
职业规划师：访谈、分析、写作、复盘
          │
          ▼
career/：原始材料 → 证据 → 分析 → 交付物
```

不通过 Life Console 展示，也不需要登录、联网服务或数据迁移。

## 2. iCloud 文件夹

```text
career/
  README.md                    # 如何查看和补充
  00-收件箱/                   # 用户刚提供、尚未整理的材料
  01-原始资料/                 # 兼容入口，不再接收原文
    README.md
  个人知识库/                  # 独立维护的原文唯一真相源
    README.md
    00-管理/

      迁移清单.json
      完整性报告.md
      恢复说明.md
```

编号只用于稳定排序。用户可以直接用 Finder、文本编辑器或支持 Markdown 的应用查看。

## 3. 原文保全规则

- 优先复制原文件；无法复制文件时保存完整正文，不先摘要或脱敏。
- 飞书节点以独立目录保存 `source.json`、`原始导出/`、`可读副本/`、`assets/`、`attachments/` 和 `子文档/`。
- `source.json` 记录节点类型、原始标题、来源标识、父节点、同级顺序、原链接、捕获时间、版本和导出格式，用于未来恢复知识库结构。
- 原文件不覆盖、不改写；更新内容放入新的日期/版本目录。
- `来源清单.md` 记录：来源编号、名称、来源方式、获取日期、版本、完整/部分/失败、保存位置和备注。
- 文件较大、链接无权限、正文被截断或附件缺失时必须明确标记，不能写成“已完整保存”。
- 可选记录文件大小和 SHA-256，用于重要材料的完整性核验；这不是日常查看的前置条件。

## 4. 知识整理规则

- `career/个人知识库/` 是内容真相源；整理文档只引用来源编号。
- 证据卡区分已确认事实、分析推断和待确认项。
- 职业分析最多同时维护一条主路径、两条探索路径。
- 交接和简历从证据层派生；修改简历不会反向修改原始资料。
- 每次咨询记录本次输入、结论、用户修正、产物和下一步。

## 5. 职业规划师行为规则

- 触发：用户提到职业规划、工作材料整理、离职交接、简历、项目案例、求职路径或职业咨询。
- 先说明本轮目标、已有输入、所需输入、输出和时间盒。
- 不从公司品牌推断工作强度；主动评估晚间会议、周末发布、跨时区和客户压力。
- 没有材料时可以提供假设和探索方向，但不得冒充对用户经历的事实判断。
- 不代替用户投递、联系第三方或对外发送材料。

## 6. 提醒

提醒只负责邀请用户开始当次咨询，并给出完整输入输出清单；具体知识仍写入 `career/`。首周五次提醒使用上海时间 14:30，周末不触达，8 月 21 日后停止。提醒中不出现工作原文、真实链接、内部名称或业务指标。

## 7. Git 与隐私

- `career/` 只在 iCloud，整体排除 Git；其中 `career/个人知识库/` 保存真实原文、图片、附件、来源树和恢复元数据。
- Git 只保留空白模板、通用职业咨询规则和本版本去敏方案。
- 不为这套能力创建数据库、线上页面或第二份同步副本。
- 用户后续需要对外产出时，再从原文生成独立副本并由用户判断脱敏范围。

## 8. 恢复

换机后只需恢复 iCloud 中完整的 `career/` 文件夹，并优先检查 `个人知识库/00-管理/迁移清单.json`、`完整性报告.md` 和各节点哈希。职业规划师重新读取 README、来源清单和当前分析即可继续；派生文档损坏时可从原文库和证据卡重新整理。未来重建飞书文档时，以每个节点的 `source.json`、原始导出和资产目录恢复父子关系、顺序与内容。
