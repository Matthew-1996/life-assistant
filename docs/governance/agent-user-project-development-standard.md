为了保障项目的长期维护，我制定了该项目Agent和用户协同的规范。
1. 理解这个规范，并把这个规范融入项目相关规则当中。把这个规范作为项目开发上优先级最高的文档，保障执行。
2. 如果出现相关文档或者流程的缺失，应该先判断是否应该由agent生成并由用户确认。涉及需要用户确认的部分，不可以自行跳过，需要得到用户反馈。

# 背景
纯agent自助开发项目，容易出现需求理解错误、产品和技术方案改动困难的情况。长期不利于项目维护。因此，我们尝试引入真实且科学的产品开发项目管理流程，作为项目长期维护和协同的核心SOP

# 角色和职能
- 产品负责人（Product Owner，PO）：由用户负责/主导输入；agent辅助完成文档，帮忙补充。
  - 负责定义产品需求、产品定位、产品方案、产品功能
- 项目负责人（Project Manager Owner，PMO）：主要由Agent负责，核心信息来源为PO和相关产品方案文档。
  - 负责协调项目团队，管理项目进度和资源，协调项目各个成员/agent按照本SOP规范推进项目，确保项目按计划进行。
  - 需要自行维护PMO文档，核心包含本次项目协作方、协作进展、项目进度、后续todo、项目卡点。方便其他成员/agent参考和维护。
- 设计师（Designer）：主要由Agent负责，核心信息来源为PO和相关产品方案文档。需要通过跟产品方案和用户沟通，来完成项目设计原则、设计规范、设计方案（UI稿、UE稿等）。
  - 负责积累产品设计经验，调研同类型产品的设计方案，为产品设计提供参考。
  - 负责理解产品需求，将产品需求先形成项目的整理设计框架。
  - 负责设计产品界面、功能模块、交互流程等。
  - 与PO、PMO合作，确保产品需求得到正确实现。
- 后端开发（Backend Developer）：主要由Agent负责，核心信息来源为PO和相关产品方案文档、技术方案文档。
  - 负责调研后端技术方案。
  - 负责从项目开始，梳理清楚长期可维护的产品的后端功能模块、数据存储、接口设计等。并且在每次项目需求迭代的时候，review后端技术方案，判断后端方案是否可持续维护或重构。
  - 负责根据产品设计，实现产品的后端功能。
  - 与PO、PMO合作，确保产品需求得到正确实现。
  - 负责维护和更新产品的后端功能，确保产品的长期稳定运行。
  - 负责和前端开发合作，确保后端功能和前端功能的协调一致。
- 前端开发（Frontend Developer）：主要由Agent负责，核心信息来源为PO和相关产品方案文档、技术方案文档。
  - 负责调研前端技术方案。
  - 负责根据产品设计，实现产品的前端功能。
  - 与PO、PMO合作，确保产品需求得到正确实现。
  - 负责和后端开发合作，确保前端功能和后端功能的协调一致。
  - 负责维护和更新产品的前端功能，确保产品的长期稳定运行。并且在每次项目需求迭代的时候，review前端技术方案，判断前端方案是否可持续维护或重构。
- 测试QA（QA Tester）：主要由Agent负责，核心信息来源为PO和相关产品方案文档、技术方案文档。
  - 负责根据产品方案+产品设计稿+技术方案，制定产品前后端的测试方案。
  - 负责根据测试方案，执行项目测试，确保产品的功能验收正常。
  - 与PO、PMO合作，确保产品需求得到正确实现。
  - 负责维护和更新产品的测试用例，确保产品的长期稳定运行。
- 数仓（Data Warehouse）：主要由Agent负责，核心信息来源为PO和相关产品方案文档、技术方案文档。
  - 按项目判断是否需要数据仓库功能，如果需要，负责设计数据仓库的架构、数据模型、数据加载流程等。
  - 负责根据产品设计，实现产品的数据仓库功能。
  - 与PO、PMO合作，确保产品需求得到正确实现。
  - 负责维护和更新产品的数据仓库功能，确保产品的长期稳定运行。
  - 负责和后端开发合作，确保数据仓库功能和后端功能的协调一致。

# 核心流程
1. 项目立项：PO定义产品需求、产品定位、产品方案、产品功能。（PRD-产品文档 或 MRD-需求文档）
2. 需求评审：评估需求合理性、产品方案可行性、项目开发成本。
	1. 产出：需求评审报告，给出各个参与方的需求评审结果。最终由用户确认需求是否进入可执行阶段，以及最终的产品方案。
  2. 参与方：所有项目成员，包括「PO、PMO、设计师、后端开发、前端开发、测试QA、数据仓库，等」。
3. 设计方案评审：设计师根据产品需求，完成产品设计原则、设计规范、设计方案（UI稿、UE稿等）。
  1. 产出：设计师完成的产品设计文档。
  2. 参与方：所有项目成员，包括「PO、PMO、设计师、后端开发、前端开发、测试QA、数据仓库，等」。产品负责人（PO）负责把控设计方案是否符合预期，后端开发、前端开发、数据仓库等，负责评估设计方案的可行性。
4. 技术方案评审：根据产品需求文档+产品方案+产品设计方案，完成前端+后端+数据仓库的技术方案，并完成方案评审。
  1. 产出：技术方案文档、技术方案评审报告、测试方案文档，给出各个参与方的技术方案评审结果。
  2. 参与方：包括「PO、PMO、后端开发、前端开发、测试QA、数据仓库，等」。主要由前后端对齐技术方案，确保技术方案的可行性；由PMO把控技术方案是否偏离产品方案，偏离时有必要则同步用户，说清楚差异点，交给用户判断最终技术方案/产品方案。
5. 项目后端开发：后端开发根据产品设计，实现产品的后端功能。
6. 项目前端开发：前端开发根据产品设计，实现产品的前端功能。
7. 项目联调：后端开发、前端开发、数据仓库等开发角色，在测试环境进行联调。保障项目正常运行。
  1. 产出：联调报告，给出各个参与方的联调结果。
  2. 参与方：「后端开发、前端开发、测试QA、数据仓库，等」
8. 项目测试：测试QA根据测试方案，执行项目测试，确保产品的功能验收正常。
  1. 产出：测试报告，给出各个参与方的测试结果。
  2. 参与方：「测试QA、后端开发、前端开发、数据仓库，等」
9. 项目验收：用户根据测试报告+测试环境可验收产物（DEMO或测试/线上环境产品），确认产品是否符合预期。
10. 产品上线：用户确认产品符合预期后，将产品部署到线上环境。
11. github项目维护：产品上线同时，在github上维护项目代码，包括代码提交、代码合并、代码审核等。（如果项目维护在git上，需要该流程）

# 项目维护
为了长期维护上上述角色和项目推进流程，需要一些必要的能力。
- 项目知识库：必须集成每一次项目的产品方案文档、设计方案文档、技术方案文档、测试方案文档等。（可按需放入其他必要的文档）
  - 文档命名：以产品方案文档为基础，产品方案文档名称+项目名称+版本号命名，例如「产品A-项目A-1.0.0.md」。保障同一次产品需求下，所以后续文档都维护在该产品方案文档下。方便后续维护和参考。
  - 文档维护：项目知识库必须及时更新，保持与项目进度同步。如果项目需求有变更，必须及时更新产品方案文档、设计方案文档、技术方案文档、测试方案文档等。
  - 项目状态：项目状态包括：待需求评审、待设计方案评审、待技术方案评审、待联调、待测试、待验收、待上线、已上线。需要标明项目下每个产品需求的状态，在实际执行过程中，可能会有pending或废弃的产品需求，后续就不用再关注。（只有在做相关调研的时候，可以通过历史废弃需求，借鉴方案合理性&可能卡点）
    - 待需求评审：待开始、进行中、已完成。
    - 待设计方案评审：待开始、进行中、已完成。
    - 待技术方案评审：待开始、进行中、已完成。
    - 待联调：待开始、进行中、已完成。
    - 待测试：待开始、进行中、已完成。
    - 待验收：待开始、进行中、已完成。
    - 待上线：待开始、进行中、已完成。
    - 已上线：已上线。
- 定期的技术方案review：在每次项目需求迭代的时候，review技术方案，判断技术方案是否可持续维护或重构。
  - 技术方案必须包含明确的模块、数据存储、接口设计等设计和规划。保障长期通过知识库可以把项目的技术方案持续维护下去。
  - 同时，在每一次新需求技术方案产出的时候，可以在技术方案调研阶段，结合新需求和业界最佳实践，来判断技术方案重构的必要性、优劣势、改动成本、风险。
