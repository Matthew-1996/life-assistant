## 1. 初次建档

```markdown
请作为我的生活助手完成一次最小化建档。一次只问一个问题，优先了解会真实改变建议的内容：

1. 我现在最想改善的一个生活问题；
2. 固定日程、照护责任和不可移动约束；
3. 睡眠、精力与工作节奏；
4. 常用日历、任务、笔记、邮件和健康/财务记录；
5. 希望你主动到什么程度、安静时段是什么；
6. 哪些动作可以直接做，哪些必须先问；
7. 哪些信息可以长期记住，哪些绝不保存。

不要一次发问卷。已有答案不要重复问。信息足够后输出：用户画像草案、当前首要目标、可用数据源、权限矩阵、第一周最小方案，以及仍待确认的三项以内信息。任何长期记忆先让我确认。
```

## 2. 晨间简报

```markdown
基于今天的日期、天气、日历、待办和我当前的优先事项，生成一份 60 秒内读完的晨间简报。

输出顺序：
1. 今天最重要的一句话；
2. 按时间排序的硬日程和必要准备；
3. 最多三个重点，其中必须有一个“完成即算今天不错”的核心事项；标明其余是次项还是可延后/取消；
4. 明确的冲突、风险或需要我决定的事；
5. 一个与当天情境有关的身体或恢复提醒；
6. 今天可以不做的一件事。

不要虚构优先级，不要用励志口号填充。信息不足时标注未知；没有重要变化时保持简短。
```

## 3. 今日重排

```markdown
我的计划被打乱了。请根据剩余时间、精力、截止日期和日程约束重排今天。

先识别不可移动项，再把其他事项分为：今天必须、可以缩小、可以延后、可以取消。输出一个现实时间表，保留缓冲和吃饭/休息时间。最多保留三个主动任务并标出唯一主项；单个可执行目标或连续工作块原则上不超过 4 小时，预计超出时先拆成可独立完成的阶段并和我商量。最后告诉我现在只需要开始哪一步。
```

## 4. 晚间收尾

```markdown
用不超过五分钟帮我结束今天。依次问我：今天完成了什么、什么在消耗我、明天有什么不能忘、现在的精力如何。然后输出：

- 值得肯定的一项事实；
- 需要迁移或删除的待办；
- 明天的第一步；
- 是否有值得写入长期记忆的内容，并在写入前征求确认。

不要把未完成事项包装成失败，也不要在睡前新增大型计划。
```

## 5. 每周生活复盘

```markdown
请综合本周日程、任务、记录和我提供的感受，做一次跨领域复盘。按身体、心理、时间、关系、环境、财务、成长与乐趣检查趋势，但只展开有证据的部分。

“本周”固定为周一至周日自然周。每日状态只使用不含自由文本备注的结构化周汇总，不读取或复述 `note_summary`；日记回顾与用户明确回答分开。没有数据保持未知，不从均值、日记或助手推断伪造用户回答。

输出：
1. 本周变好的三件事以内；
2. 反复出现的摩擦与可能原因，区分事实和推断；
3. 下周已有硬约束与冲突；
4. 一个最值得做的系统改进；
5. 一个要停止、减少或委托的事项；
6. 一个可在七天内验证的小实验及成功标准。

不要给十几个新目标。需要修改日程、任务或自动化时，先给变更草案并等待确认。

如果用户回答了周复盘问题，只保存其明确提供的字段；延迟回复仍归原问题所属自然周。周回答不是当天状态，目标意向也不自动改变目标台账。
```

## 6. 习惯设计

```markdown
我想建立这个习惯：[习惯]。请先确认它服务的真实目标和当前阻力，再设计一个低摩擦版本：触发情境、两分钟起步动作、理想动作、最低完成标准、环境调整、失败后的恢复规则，以及两周后的评估指标。

优先改变环境和流程，不依赖意志力。一次只设计一个核心习惯，不用连续打卡羞辱或惩罚机制。
```

## 7. 个人决策支持

```markdown
我要决定：[决策]。请先提取目标、硬约束、可逆性、截止时间和最大风险。列出 2–4 个真实选项，用我重视的标准比较，并指出缺失信息会如何改变结论。

如果决定可逆，建议一个低成本试验；如果不可逆或高影响，给出核验清单和停下来咨询专业人士的条件。最后给出推荐，但保留我的最终决定权。
```

## 8. 关系维护

```markdown
基于我明确授权的联系人、纪念日和近期承诺，帮我找出本周最值得维护的 1–3 段关系。对每一项给出具体、真诚、低负担的行动建议，并说明依据。

可以起草消息，但不要代我发送。不要根据聊天片段擅自推断关系状态，也不要把第三方隐私写入长期记忆。
```

## 9. 饮食与采购

```markdown
根据人数、预算、饮食限制、家中已有食材、可用烹饪时间和本周日程，设计一个现实的 [天数] 天饮食方案。

尽量复用食材和剩菜，标注需要提前处理的步骤，输出按区域合并的购物清单和可替换项。涉及过敏、疾病或孕期等健康约束时，明确不确定性并建议专业确认。
```

## 10. 出行与跑腿合并

```markdown
把这些地点和事项整理成低折返、留有缓冲的执行顺序：[清单]。核验营业时间、预约、交通和天气等时效信息，标出必须携带的物品及可能失败点。

如果需要预约、下单、支付或向他人发消息，只准备草案并在执行前逐项确认。
```

## 11. 卡住、拖延与重新开始

```markdown
我想做但一直没有做到：[事情]。先不要给我更多待办，请帮我判断主要阻力来自能力、机会还是动机。用一两个问题确认：我是否真的想做、现在最具体的阻碍是什么、过去哪一步最容易中断。

然后给我两个不同成本的方案。等我选择后，再写成一个“如果 [可观察触发]，那么我就 [最小动作]”计划，并包含：状态好时的理想版本、低精力最低版本、环境准备、错过后的下一次恢复触发点，以及七天后的评估问题。

不要把拖延解释成懒惰，不使用连续打卡、惩罚或内疚推动我。如果我并不想做，帮助我重新决定、缩小或放弃，而不是劝服我。
```

## 12. 生活目标维护

```markdown
请维护我的生活目标组合，而不是把所有愿望都变成当前待办。

先读取现有目标及其状态。对于我新增或想调整的目标，区分它是长期结果、一次性任务、暂时症状还是实现手段；用一个问题确认它为什么现在重要。然后比较它与现有目标的现实收益、时间敏感性、精力成本和冲突。

给我 2–3 个选择：保持当前排序、替换当前重点，或先放入候选。由我决定后，输出新的当前重点、最多两个辅助目标、暂不推进的目标、对现有计划的影响和下次复盘日期。允许目标继续、缩小、降级、暂停、完成或被替换；不要用沉没成本或旧承诺劝我坚持。

更新长期目标记录前，先展示准备保存的摘要并征求确认。临时困难、一次性情绪和未经证实的推断不要写入长期记忆。

如果输入来自阶段复盘，先保存用户明确回答，再派生可恢复动作；不把“回答已保存”当成目标、策略或提醒已应用。健身和职业两个候选分支互斥：只安排 `next_track` 明确选中的分支；选健身时屏蔽 `career_timing`，选职业时屏蔽 `fitness_conversation`，选都不聊时两者都不生成动作。
```

## 13. 睡眠与恢复支持

```markdown
请帮我改善睡眠和白天恢复，但不要诊断、改药或把计划变成新的考核。

先获取会改变建议的最少信息：问题持续多久、每周频率、通常入睡和起床时间、白天功能、午睡与咖啡因/酒精、工作和照护约束，以及是否有响亮打鼾伴呼吸暂停、异常动作、难以控制的白天嗜睡、持续情绪低落或自伤想法。已有信息不要重复问；安全问题直接而简短地确认。

对可能变化或高影响的医学信息，检索当前官方卫生机构或临床指南并注明来源。如果出现立即安全风险，优先建议联系当地急救、心理危机支持和可信任的人；如果症状反复、持续或影响日常功能，建议睡眠门诊或精神心理专业评估。长期失眠可介绍 CBT-I 是常用一线治疗，但不要让我在缺乏专业评估时自行执行完整睡眠限制治疗，也不要建议我自行开始、停用或调整药物和补充剂。

若适合先做一般行为支持，设计一个 7–14 天低负担实验，最多三个日常锚点，例如现实的起床锚点、日间光照/活动、睡前降速与减少清醒躺床。提供状态差时的最低版本、失眠当晚脚本、1分钟记录方式、复盘日期和明确的就医升级条件。衡量白天精力、情绪、清醒躺床和生活实感，不只追逐睡眠时长。
```

## 14. 对话式生活日记

```markdown
请把我接下来提供的生活经历整理为一篇可回顾的日记，并保留我的原意。

触发规则：当消息以“日记”“日记记录”“生活记录”“记录一下”开头，或我明确说“写进日记”“帮我记下来”“存到日记”时，直接记录；如果我只发了触发词而没有正文，再请我补内容。没有触发词时，只有在我明显叙述一段希望保留的亲身经历时才可隐式记录，并在回执中说明“已记录”，允许我立即撤回。

归档时：
1. 保留用户原话，不润色成另一种人格；
2. 提取日期、标题、明确事实、明确感受、人物、地点或场景、生活主题、标签和可能影响未来规划的线索；
3. 把事实、用户明确表达和助手推断分开，推断不得写成结论；
4. 使用用户提供、或可从“今天/昨天”等明确相对表述解析出的发生日期；完全没有日期线索时使用当前 Asia/Shanghai 日期。只有用户提供具体时刻时才保存事件时间；没有具体时刻时保存 `time=null`、`time_precision=unknown`，只知道大约时刻时标为 `approximate`，并把真实记录时间另存为 `recorded_at`，不得用发送或记录时间制造事件时刻；
5. 原文归档副本保存在当前 iCloud 项目，日记工具不自动发布；用户已确认的私密 Google 表格只保存轻量索引并且不反向写入，网页默认不显示原文或敏感摘要，未经当次明确同意，不向任何外部站点发布这些内容；
6. 密码、令牌、完整证件/银行卡信息和第三方秘密不落盘，必要时只记“敏感信息已省略”；
7. 同步本地月度日记、轻量索引和生活计划表后，只回复日期、标题和保存结果，不强迫回答追问；任何一步失败都如实说明。

整理节奏由用户明确选择，并保存到 `journal/review-policy.json`；尚未选择长期频率时只在用户提出时整理，不默认续期或同时安排周/月任务。已选择周度时，在下一个周一先用 `review-plan` 处理已经结束且有新增或来源变化的完整自然周；已选择月度时，在次月 1 日或之后处理刚结束的完整自然月。对每个 due 周期，使用计划返回的完整 `entry_ids`，并把同一次计划的 `source_set_etag` 原样传给 `review`；若计划后来源发生变化，停止本次写入并重新计划，不能手工删减来源。周回顾整理发生的事、补充与消耗、反复线索、未完事项和一个规划启示；月回顾整理生活片段、变化、希望增加/减少的事和待用户确认的长期认识。展示候选时用确认台账每次最多给 3 个，用户明确 accept/reject 才记录。接受后严格按 `pending → awaiting_proposal → proposed → applied` 推进：accept 只记录 awaiting_proposal；随后持久化拟写入 `USER.md`、`MEMORY.md` 或 `GOALS.md` 的目标和精确文字，并从可恢复提案返回该内容供用户明确同意。只在同意后才真正编辑长期文件，且验证目标已包含该精确文字后才标记 applied；中断时从台账恢复，不凭旧对话猜回。没有新增内容就保持安静；日记内容不自动变成目标、诊断或长期记忆。
```
