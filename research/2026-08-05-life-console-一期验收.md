## 二、问题与修复

### 1. 锚点假保存

- 原问题：前端先改变本地状态，Hub 失败时不回滚；“未记录”也会形成模糊的可点击语义。
- 修复：正式模式只在 Hub 保存成功并刷新 Dashboard 后显示新状态；失败时保持源状态并显示错误。`unknown` 固定为非提交状态，清空仍需明确更正流程。
- 复验：停止临时 Hub 后点击“生活动作 → 完成”，页面继续显示“未记录”，合成源记录保持 `null`；重启后可恢复读取。

### 2. 进展日期与缺失样本

- 原问题：周二被硬编码为当前日；只返回有记录的日期，折线可能跨真实缺失日连接。
- 修复：依据 Dashboard 日期计算自然周；读取模型固定生成截至当天的最近七个日历槽位，缺失日写为 `null`，同时返回真实记录数和无记录数。
- 复验：2026-08-05 正确标记周三；页面显示 2026-07-30 至 2026-08-05、2 条记录和 5 个无记录日。

### 3. 本地会话与同源策略

- 原问题：OpenAPI 声明全局 LocalSession，但 Dashboard 无会话可读；Origin 只校验 loopback 主机、不校验端口；前端会话过期后不会刷新。
- 修复：Dashboard 和 confirmations 均要求短时会话；Host 与写入 Origin 必须匹配 Hub 实际端口；前端在到期前或首次 403 后只刷新一次会话并重试。
- 复验：未认证 Dashboard 返回 403；另一 localhost 端口的 Origin 返回 403；客户端 403 刷新流程通过。

### 4. 请求校验与错误映射

- 原问题：未知状态字段会到达命令运行器并被返回为 503。
- 修复：Hub 在运行工具前校验日期、revision、评分、时间、锚点、日记、预览和删除确认字段；`INVALID_REQUEST` 映射为 400 且不可重试。
- 复验：未知状态字段及错误日记类型均返回 400，未调用真实工具。

### 5. 状态和文案真实性

- 原问题：正式记录页仍声称只使用内存合成数据；系统页把只读快照显示为“可读写”；README 与已实现能力冲突。
- 修复：正式/合成模式分别显示；iCloud 状态拆为 `readable / writable / partial / unavailable`，当前只显示“已验证可读取”；README 已按真实能力和审批边界重写。

### 6. 旧报告追加发现

- 当前重点解析现在优先读取 `## 当前重点` 下的 `### 目标标题`，不再把“状态”元数据当标题。
- Hub CLI 新增机器本地 `--root`；LaunchAgent 生成器显式写入数据根，日志位于权限受限的运行目录。
- 正式 OpenAPI 方案副本已与应用契约逐字节同步。
