## 二、已验证的核心修复

### 1. 数据与交互真实性

- 正式模式只在 Hub 保存成功并刷新 Dashboard 后显示新状态；失败保持源状态。
- Dashboard 按实际日期生成最近七个日历槽位，缺失日保持 `null`。
- 当前重点优先读取目标标题，不把状态元数据误作标题。
- iCloud 与自动化状态由机器本地启动配置显式注入；默认仍是 `readable / unknown`，只有真实验收后才允许标为 `writable / ready`。

### 2. 本地安全边界

- Hub 只绑定 `127.0.0.1`，读操作需要短时会话，写操作同时要求同端口 Origin 与 CSRF。
- 输入在调用原子工具前完成日期、revision、评分、时间、锚点、日记和删除确认校验。
- 日记正文不进入 URL、日志、浏览器持久化或 Git 测试夹具。

### 3. macOS 后台运行

- LaunchAgent 显式设置 Python 模块路径，不再依赖工作目录隐式导入。
- macOS 受保护文件访问不再绑定通用 Python：新增专用、可重建、ad-hoc 签名的 `Life Console.app` 后台启动器，由它托管 Python Hub 子进程并转发终止信号。
- 生成器支持分离应用根、iCloud 数据根、专用启动器与 Python 路径，日志仍保留在权限受限的机器本地运行目录。
- 读取模型失败会记录本地异常类型与调用栈，HTTP 响应仍只返回去敏通用错误。

### 4. Google 展示切换

- 工作站验收后，Google 表格配置支持原子切换为 `paused / on_demand`。
- 暂停状态保留私人表格绑定、历史内容与同步收据，不自动刷新，也不把 iCloud 新变化报告为同步欠账。
- iCloud 仍是唯一真相源；Google 可由用户以后明确要求恢复。

## 三、真实上线验收

1. 正式 LaunchAgent 启动后，健康接口返回 `ready`，Dashboard 能读取当前 iCloud 真相源。
2. 通过正式后台发送同一测试日记请求两次；返回同一命令收据，只创建一条源记录。
3. Dashboard 能读回该记录；随后按稳定 ID 逻辑撤回，活动日记列表恢复为空。
