# 生活助手移动看板

这是生活助手项目的移动优先、只读查看页。它把当前重点、阶段路线、健身与职业互斥候选分支、对话式回访和日记使用说明压缩到一个适合手机浏览的页面；用户不需要在网页表单里重复录入生活数据。

## 真相来源与同步边界

- `../../GOALS.md` 是生活目标状态、优先级和复盘节点的真相来源。网页只是可视化副本，不能自行升级、暂停或完成目标。
- `../../outputs/019fb832-be4f-74f1-add5-58cb6fb6fc09/生活计划表.xlsx` 是计划和记录的可视化工作簿，不反向决定目标状态。
- 页面中的阶段和候选分支目前由 `app/life-plan.js` 与 `app/page.tsx` 显式维护，尚未自动读取 `GOALS.md`。`confirmedPhaseTruth` 是 `GOALS.md` 的项目内镜像：当前只确认阶段 01，复盘日为 2026-08-14；健身与职业同一阶段至多启用一条，未选中时不排期、不提醒。
- 日期只决定已确认阶段内的进度，不能确认新阶段。若阶段 01 结束后 `GOALS.md` 尚无新决定，页面从 2026-08-15 起显示 `awaiting_review`，继续最低恢复锚点；阶段 02–05 仍只是建议，不会按日期自动开始。
- 七日轻量路径按 `Asia/Shanghai` 当天动态生成。只有用户确认阶段变化后，才先更新 `GOALS.md`，再同步 `confirmedPhaseTruth`、页面文案和测试；完整建议路线结束后显示“路线已到复盘节点”。

## 只读与隐私

- 网页没有生活记录表单，也不把网页当作日记、每日状态或自然周复盘的源台账。用户在生活助手对话中回复，由项目工具整理到 iCloud 项目和工作簿。
- 不要把日记原文、自由文本状态备注、周/月回顾、聊天记录、秘密、任务标识或连接器数据写进页面源码、测试夹具或构建日志。
- 日记工具不会自动把原文发布到网页。未来若要展示任何真实日记摘要或回顾，必须针对具体范围取得用户当次明确授权。
- `local-only` 只表示项目工具不主动向网页或连接器发布；对话平台、iCloud、设备版本和 ZIP 备份仍按各自规则保留。完整边界见 `../../journal/PRIVACY.md`。
- 本地修改和构建不等于发布。重新发布或变更访问范围前，必须取得当次明确同意；过去的发布授权不自动续期。
- `PUBLICATION_STATE.json` 是不含凭据和站点标识的可迁移发布状态：它记录部署相关本地源码指纹、最后已知可见范围，以及当前本地源码是否已发布。当前为 `local_changes_unpublished`，所以线上仍按此前版本处理。

## 内容维护

调整生活路线时：

1. 先读取 `../../GOALS.md` 和相关计划，确认哪些是用户已确认目标，哪些只是未来建议。
2. 用户确认新阶段后，先更新 `GOALS.md`，再在 `app/life-plan.js` 更新 `confirmedPhaseTruth`；不得用当天日期替代用户确认。阶段日期、动态路径和页面文案按同一决定同步维护；健身与职业候选分支保持互斥，不能因日期到达同时启用。
3. 补充日期边界与渲染测试，运行 `npm test`。只有测试通过且用户当次批准时，才进入另行的发布流程。
4. 每次改变 `app/`、`public/` 或部署相关配置后，刷新 `PUBLICATION_STATE.json` 的本地源码指纹并保持 `local_changes_unpublished`；只有托管部署明确成功后，才把状态改为 `published_current`，同时把已发布指纹设为当前指纹。

关键文件：

- `app/life-plan.js`：上海日期、连续七日路径、阶段边界和 `GOALS.md` 已确认阶段镜像。
- `app/page.tsx`：只读页面内容和结构。
- `app/globals.css`：移动端与桌面端样式。
- `tests/life-plan.test.mjs`：日期、跨月和路线结束边界。
- `tests/rendered-html.test.mjs`：服务端渲染、隐私文案和只读约束。
- `.openai/hosting.json`：Sites 托管项目元数据；不代表当前在线访问策略已经被本地验证。
- `PUBLICATION_STATE.json`：本地源码与最后已知发布版本的关系；不包含 `project_id`，也不能替代联网核验。

## 本地验证

需要 Node.js `>=22.13.0`。在本目录执行：

```bash
npm ci
npm test
```

`npm test` 会先构建，再运行全部 `tests/*.mjs`。仅需本地查看时可以运行 `npm run dev`；不要把启动本地服务误认为已发布。

## 换机恢复

整个 `codex-生活助手` iCloud 项目才是可迁移上下文。`node_modules/`、`dist/`、`.wrangler/` 和机器本地缓存不是迁移真相；它们可以在新电脑上重新生成。

1. 等待 iCloud 项目完整同步，并按项目根目录的 `PORTABILITY.md` 恢复。
2. 进入本目录运行 `npm ci` 和 `npm test`。
3. 核对 `.openai/hosting.json` 存在；应用内自动化和实际托管访问策略属于外部或机器本地状态，仍需按项目说明单独恢复和验证。
4. 未取得当次发布同意时，到本地验证结束为止，不执行托管发布。
